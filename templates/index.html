💡 What is this Laboratory & Why does it exist?
In textbook theory, algorithms are represented as mathematical formulas like O(N log N) and O(N²). This lab bridges theory and reality: it benchmarks actual sorting algorithms on your machine across growing datasets (from N = 20 up to 400 elements), counting every single element comparison, memory swap, and microsecond of execution time.
🏆 1. The Scaling Champions
Quick Sort & Merge Sort (O(N log N)): Notice how their lines remain flat and low even at N=400 (~2,500 operations). They effortlessly scale to millions of elements.
🐢 2. The Quadratic Wall
Bubble Sort (O(N²)): Watch the curve explode upward! At N=400, it requires over 80,000 operations (30x more CPU work) to accomplish the exact same task!
🔍 3. What the Numbers Mean
Comparisons = checks between two items. Swaps/Writes = memory modifications. Duration = physical CPU time in milliseconds.

Asymptotic Analysis & Big-O Notation

In computer science, algorithm efficiency is evaluated asymptotically to describe how resource requirements (CPU cycles and memory) scale as the input size $N$ approaches infinity.

Asymptotic Growth Comparison

Observe how quadratic $O(N^2)$ curves diverge rapidly from linearithmic $O(N \log N)$ and linear $O(N)$ as input increases:

The Three Asymptotic Notations

  • Big-O ($O$): Strict upper bound. Guarantees the algorithm will run no slower than this function in the worst case.
  • Big-Omega ($\Omega$): Strict lower bound. Proves the minimum resources theoretically required by any algorithm solving this problem.
  • Big-Theta ($\Theta$): Tight bound. Exists when an algorithm's upper and lower bounds asymptotically coincide.

Sorting Paradigms & Lower Bounds

Sorting is the foundational algorithmic problem of rearranging an arbitrary collection into a strictly monotonic order.

Comparison vs Non-Comparison Sorts

Any comparison-based algorithm (Bubble, Quick, Merge, Heap) is bounded by the mathematical lower bound $\Omega(N \log N)$. Non-comparison sorts such as Counting Sort break this barrier by utilizing direct memory indexing, running in linear time $O(N + K)$ when the key range $K$ is bounded.

Algorithm Stability & Memory Hierarchy

A sort is stable if duplicate elements preserve their relative order from the input. Furthermore, modern CPU hardware performance heavily favors contiguous linear array access (Quick Sort) over cache-evicting binary tree jumps (Heap Sort).

Searching: Sequential vs Interval vs Heuristic

Locating a target value within a collection depends critically on whether the data is unordered, ordered, or uniformly distributed.

Comparing Search Strategies

  • Linear Search: $O(N)$ worst-case. Required whenever data is unsorted.
  • Binary Search: $O(\log N)$. Repeatedly bisects a sorted array. 32 comparisons can search 4 billion elements.
  • Jump Search: $O(\sqrt{N})$. Balances block jumps with linear scan. Superior when jumping backward is costly.
  • Interpolation Search: $O(\log \log N)$ average on uniformly distributed numbers by calculating probe slope.

Graph Traversals & Shortest Paths

Graphs $G = (V, E)$ represent discrete relationships between entities. Traversing and discovering optimal routes are core engineering problems.

Traversals & Optimal Routing

  • BFS (Breadth-First Search): Level-order exploration using a FIFO queue. Guarantees shortest path on unweighted graphs.
  • DFS (Depth-First Search): Deep recursive exploration with backtracking. Used for cycle detection and topological sorting.
  • Dijkstra’s Algorithm: Greedy shortest path using a min-priority queue to iteratively relax edge distances on non-negative weighted graphs.
  • A* Search: Optimizes Dijkstra by incorporating an admissible heuristic $f(n) = g(n) + h(n)$ to direct exploration towards the target.
